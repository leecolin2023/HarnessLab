## 变更与追踪原则

- 新增正式 SRS 时分配唯一 `SRS-xxx` ID；文档内部需求和验收项独立编号。
- 同一个稳定 SRS 可对应多个实现方案，例如 DSH 和 LangGraph，不按具体技术栈复制一套需求。
- 记录需求批准情况与版本；任何没有核验的业务假设都应显式保留为 `Draft/TBD`。
- 实验与测试使用 `AC-xxxx` 反向指向 `REQ-xxxx`；产品实现再链接具体 Issue / PR / commit。
- SRS 有修改时重新审核其实现映射，避免两个框架表面上同名但实际语义不同。
